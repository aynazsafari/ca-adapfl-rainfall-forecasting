# Completed supplement QA

The standalone supplement audit is prepared and synthetic-validated, and has not opened actual study sources, arrays, fits, evaluation truths or scores. A missing supplement evaluation completion receipt causes refusal before scientific file reads. It imports no scientific model module, constructs no models, performs no fitting/inference and leaves run artifacts unchanged.

After root authorizes completed-result auditing and the supplement completion exists:

```powershell
work/env/Scripts/python.exe -X utf8 work/real_run_qa/audit_completed_supplements.py --run outputs/03_benchmark/caadapfl_benchmark/runs/supplements_v2 --primary-run outputs/03_benchmark/caadapfl_benchmark/runs/revision_v2 --output work/real_run_qa/completed_supplements_v2
```

The output directory must be fresh. All scientific source/code/runtime identities, canonical inputs, source-quality outputs, cohort plans, prepared files, completed-evaluation files and all 90 unique fit completion/file hashes are authenticated. Original source-plan bytes are authenticated by their frozen SHA; the canonically serialized run copy must have identical parsed content, with its separate hash recorded. Hyperparameters must match the frozen primary receipt, with no supplement retuning. Paths can relocate without becoming scientific identity.

The audit independently derives each common target cohort from twelve admitted source months at target minus15 through minus4 across every client. Both arms must share exactly the same labels, target calendars, common raw features, contexts, drivers and training target statistics. IMD has85 contiguous evaluation months throughJanuary2024, solar/GLDAS96. Interior calendar gaps are rejected rather than treated as adjacent months.

All six dataset archives are checked for exact finite shapes and role separation. Own input means/standard deviations are recalculated from latest-row gradient TRAIN covariates only; own target mean/std and linear q80 use gradient TRAIN labels only. Archived transformations/heavy flags and target inverse summaries must match. Fit labels and sealed evaluation truth are cross-checked against canonical CHIRPS, and evaluation feature archives must contain no y/y_z/heavy. Three boundary Decembers stay outside labeled roles.

Each case has12 separately identified labels: three methods × two arms × global/personal identities, each with five seeds and five clients on its own declared dates. Per-client regression, heavy confusion/tail metrics, tied PR/AP/AUC, macro-versus-pooled aggregates and five-seed summaries are independently recalculated. Undefined numerical metrics are checked as undefined, not floored or replaced; exported reason fields must be present. Raw negatives remain included and a separate independent diagnostic is saved.

All18 prespecified contrasts are within-case ADDED minus its own matched REFERENCE. Global/personal remain separate. The audit reconstructs108,000 paired PCG64 draws: 2,000 replicates each12/6/24 month blocks for18 contrasts, using common dates and paired resampled seeds. It verifies every draw, percentile interval, point delta and per-seed metric/delta. CI midpoint and draw mean are recorded as diagnostics; neither is required to equal the observed point. Constant-observation R2 resamples reject explicitly, matching the frozen evaluator. No new p-values, multiplicity family or cross-case ranking is introduced.

Fit QA counts90 bundles once, with180 prediction identities uncharged a second time. It checks actual60-round updates, exact299/272/80 TRAIN counts, batch/epoch optimizer arithmetic, released validation/monitor labels, both independently selected checkpoints, all message counts/payloads, measured timing and summed cost exports. Target inverse summaries total80 bytes per fit. CAAA sensitivity setup is an alias with no extra charge. Schema q80 values are exported; outdated locality prose is not endorsed. Payloads are simulation accounting, not measured network usage or a privacy guarantee.

On success, byte-identical `completed_supplement_audit.json` and `complete.json` contain status PASS, supplement run SHA, primary run SHA, exact evaluation-completion SHA, checked files/formulas/scope/limitations, actual table coverage and completed sections. Root can copy unchanged to `runs/supplements_v2/independent_qa/complete.json`. Failure records completed sections and the first blocking discrepancy without claiming unfinished checks passed.

No real fit or score is used by these fixtures.
